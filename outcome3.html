My evidence

A* Search · Finding the Fastest FPGA Verification Workflow

Before an FPGA demo, I want to find the fastest workflow that produces a verified bitstream, the file used to configure the FPGA. In this hypothetical example, my state space represents the different stages of the workflow. The initial state is Start. An action such as running a simulation causes a transition to a new state. Each action has a step cost in minutes. The goal test passes when the bitstream has been built and verified.

  • Full build and checks. Start → Done costs 11 minutes.
  • Clean build. Start → Clean Workspace → Done costs 2 + 8 = 10 minutes.
  • Simulation first. Start → Simulated → Built → Done costs 3 + 4 + 2 = 9 minutes.

A* ranks the frontier, the states it has discovered but has yet to expand, using f = g + h. Here, g is the time spent reaching a state, and h estimates the time remaining. I use estimates of 5 minutes for Simulated, 8 for Clean Workspace, 2 for Built, and 0 for Done. These estimates are admissible because none exceeds the actual time remaining from its state. For example, Simulated has 6 minutes of work left, so 5 is a valid estimate.

  1. Expand Start. The frontier contains Simulated (3 + 5 = 8), Clean Workspace (2 + 8 = 10), and Done (11 + 0 = 11).
  2. Expand Simulated because it has the lowest score. This adds Built to the frontier with a score of 7 + 2 = 9.
  3. Expand Built. This finds a better path to Done and updates its score from 11 to 9.
  4. Remove Done from the frontier and return the 9-minute simulation-first workflow.

The 11-minute route reaches the goal in a single step, so breadth-first search would find it first. A* continues after discovering that route because the frontier still contains states that could lead to a faster solution.

Q-Learning · Controlling the Fan in My AI Companion

Jay is my AI companion project, designed to run locally on a Raspberry Pi. I could build a simulator to study how Jay might manage its cooling fan during a fixed workload. The agent observes a temperature state of cool, warm, or hot, then takes an action by choosing low or high fan speed. The simulator returns a reward based on the next temperature. A cool state earns +2, warm earns 0, and hot earns −5. High speed costs another point to represent additional power use.

A Q-value estimates the expected discounted total reward from taking an action in a state and following the best actions afterward. Suppose the board starts warm and high fan speed cools it down. The immediate reward is +1 because cooling earns +2 and high speed costs 1. If Q(warm, high) starts at 0 and the best estimated Q-value in the cool state is 2, a learning rate of 0.5 and a discount factor of 0.9 give this update:

Q(warm, high) = 0 + 0.5 × [1 + 0.9 × 2 − 0] = 1.4

On another trial, suppose low speed lets the board go from warm to hot, earning −5. If Q(warm, low) and the best estimated Q-value in the hot state both start at 0, the update is:

Q(warm, low) = 0 + 0.5 × [−5 + 0.9 × 0 − 0] = −2.5

With those estimates, exploitation means choosing high speed when the board is warm because 1.4 is greater than −2.5. An epsilon-greedy policy also allows exploration by occasionally choosing a random speed. Over repeated trials, the agent can learn that high speed is worth the extra power when the board is warm and that low speed can be preferable when it reliably keeps the board cool.

Minimax · Anticipating a Basketball Defender

In a simplified basketball drill, I need to decide whether to shoot or pass. I represent the decision as a two-turn game tree. The offense is the maximizing player and moves first. The defender is the minimizing player and responds. Each leaf node has a hypothetical utility that rates how favorable the outcome is for the offense.

  • Shoot. A defender who contests gives the offense a utility of 0. A defender who stays back gives it 3.
  • Pass. A defender who cuts off the passing lane gives the offense a utility of 1. A defender who stays with the shooter gives it 2.

Minimax assumes the defender picks the response that gives the offense the lowest utility. Shooting therefore has a minimax value of 0, and passing has a value of 1. The offense selects pass because it gives the better result against the defender’s strongest response.

Alpha-beta pruning can reach the same decision with fewer evaluations. If the algorithm checks passing first, the offense has an option worth 1. When the algorithm checks shooting and sees that a contest gives it 0, the shooting branch can finish with a value of at most 0. The defender already has a response that makes shooting worse than passing, so the algorithm can skip evaluating what happens if t he defender stays back.
